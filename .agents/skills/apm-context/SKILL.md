# APM agent context

The shared context is the `Yazee-Me/Playbook` package, pinned in `apm.yml`;
`apm.lock.yaml` records the commit and the content hashes. Each repository
consumes it and generates its own `AGENTS.md` and `.agents/skills/`.

## Rules

- `AGENTS.md`, any per-directory `AGENTS.md`, and `.agents/skills/` are
  generated. Never edit them by hand. Edit `.apm/instructions/` in the
  repository, or Playbook for anything shared.
- A fresh clone or worktree has no `apm_modules/`. Run `apm install --frozen`
  before `apm compile`, or the compile omits the Playbook instructions.
- `apm_modules/` is generated and gitignored.
- Deploys target `opencode`, whose output is `AGENTS.md` plus `.agents/skills/`:
  the same surface every harness reads, so no per-client directory carries
  context. Do not add Claude-specific targets or per-skill symlinks.
- The skill destination is `.agents/skills/<name>/` only: one materialized copy
  serves every harness.

## Commands

```bash
apm install --frozen     # resolve the pin; needed once per clone or worktree
apm compile              # write AGENTS.md and .agents/skills
apm compile --validate   # check the primitives without writing
apm audit --ci           # verify the committed output against the lockfile
```

A repository wraps these in a task, for example `mise run agent:sync` and
`mise run agent:check`. Use the task where one exists.

## Change the shared context

1. Edit `.apm/` in Playbook; keep shared rules in instructions and procedures in
   skills.
2. Validate and compile there to prove the package renders.
3. Tag the package, then bump the pin in each consumer, `apm install`,
   `apm compile`, and commit `apm.yml`, `apm.lock.yaml`, `.apm/`, `.agents/`, and
   the generated `AGENTS.md` together.
- `.omp/skills/openspec-*` and the `/opsx-*` commands are OpenSpec's output,
  generated by `openspec update`. They stay repo-local and are never part of
  Playbook.
